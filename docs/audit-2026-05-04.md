## 🔴 Top 5 actions critiques (ordre de priorité)

1. **Implémenter réellement l'anti-lockout 30s** — actuellement `rollback_timeout_secs` est un champ de config marqué `never read` par le compilateur. C'est une feature mise en avant comme garantie de sécurité, son absence est trompeuse. Câbler timer + probe de connectivité + rollback automatique dans `crates/infra/src/nftables/adapter.rs` autour de `apply_ruleset`.
2. **Authentifier le peer gRPC** — ajouter un `Interceptor` tonic utilisant `SO_PEERCRED` dans `crates/daemon/src/grpc/server.rs:39-90`. Refuser tout client hors `root` ou groupe `syswall`. Faire échouer durement le démarrage si le `chown` du socket échoue (actuellement seul un `warn!`).
3. **Durcir `system/syswall.service`** — ajouter `CapabilityBoundingSet`, `User=syswall`, `ProtectSystem=strict`, `RestrictAddressFamilies`, `SystemCallFilter`, `NoNewPrivileges` (sauf si JIT eBPF requis). La variante PKGBUILD Arch a déjà ces réglages — les porter au service principal.
4. **Éradiquer les `unwrap()` en code de prod** — 455 occurrences (infra 269, app 120, daemon 31, domain 29). Sur un démon firewall, une panic = perte de protection réseau. Activer `#![deny(clippy::unwrap_used)]` sur `domain` et `app` après nettoyage.
5. **Aligner la version workspace** — `Cargo.toml:18` est en `0.1.0` mais les paquets `system/arch/syswall-0.2.0-1...zst` sont en `0.2.0`. Ajouter une vérif CI : version workspace == tag git.

## 2. Audit sécurité

### Modèle de menace
Daemon root (CAP_NET_ADMIN/BPF) ↔ UI Tauri non-privilégiée via socket Unix gRPC. Adversaires : utilisateur local du groupe `syswall`, processus créant des comm/cmdline forgés, payloads dans noms de règles.

### 🔴 Vulnérabilités critiques

**V1. Pas d'authentification peer sur gRPC**
- `crates/daemon/src/grpc/server.rs:39-90`
- Socket `0o660` + `chown` best-effort. Aucun `SO_PEERCRED`.
- Tout binaire dans le groupe `syswall` peut désactiver le pare-feu via `set_network_enabled`.
- CVSS ≈ 7.8.

**V2. Daemon en `User=root` sans durcissement systemd**
- `system/syswall.service` minimaliste — aucune capability bounding, aucun namespace, aucun seccomp.
- Toute exploitation mémoire en aval → root complet.
- CVSS ≈ 7.0 (multiplicateur d'impact).

### 🟠 Risques modérés
- `read_unaligned` sur événement eBPF sans champ `version`/`magic` (`crates/ebpf/src/lib.rs:122-127`).
- TOCTOU procfs : PID recyclable entre `/proc/<pid>/exe` et `/proc/<pid>/cmdline` (`crates/infra/src/process/resolver.rs:91-225`).
- Logs PII (DNS, paths binaires, hostnames) sans rotation logrotate documentée.
- Blocklist files lus sans validation symlink (root lit `/etc/shadow` si symlinké).
- Tauri CSP désactivée (`tauri.conf.json` → `"csp": null`).
- gRPC sans `max_decoding_message_size` ni `concurrency_limit` → DoS local trivial.

### 🟢 Bonnes pratiques constatées
- `NftCommandBuilder` : args en liste à `Command::new`, jamais de shell. **Pas d'injection nft possible**.
- SQLite : usage systématique de `rusqlite::params!` ; le seul `format!` SQL interpole un fragment WHERE composé de littéraux statiques.
- Versions deps à jour, pas de CVE critique connue (cargo-audit non installé localement, à vérifier en CI).
- Tauri capabilities restrictives : pas de `fs`, `shell`, `http`.
- Aucun secret hardcodé.

## 3. Audit fonctionnel

### ✅ Confirmé (avec preuves code)
- Capture eBPF tracepoint `inet_sock_set_state` + `HybridProcessResolver` + fallback procfs.
- Moteur de règles : 7 critères tous présents dans `RuleCriteria` (`crates/domain/src/entities/rule.rs:102-117`) avec tests.
- Whitelist système : DNS, DHCP, NTP, loopback IPv4/IPv6 (`crates/app/src/services/whitelist.rs`).
- 6 actions de décision : `AllowOnce`, `BlockOnce`, `AlwaysAllow`, `AlwaysBlock`, `CreateRule`, `Ignore`.
- Cache DNS LRU 4096 / 5min (config conforme au README).
- gRPC double service `SysWallControl` + `SysWallEvents`.
- 7 vues UI (Dashboard, Connexions, Règles, Apprentissage, Audit, Paramètres, + Popup).
- Audit batch (size=100, flush=2s).
- Rollback nftables sur échec immédiat (`adapter.rs:147,161`).

### ⚠️ Partiel
- **Anti-lockout timer 30s** : champ `rollback_timeout_secs` config-only, signalé `never read` par le compilateur. **Aucun timer ni probe de connectivité**. Le rollback n'existe que sur échec immédiat de `nft`.
- **Debounce auto-apprentissage** : `debounce_window_secs` jamais lu → spam de notifications garanti en prod.
- **Champs config dormants** : `log_dir`, `watchdog_interval_secs`, `theme`, `journal_retention_days`, `default_timeout_action`, `overflow_action` — tous `never read`.

### ❌ Absent mais annoncé
- Anti-lockout 30s (cf. ci-dessus) — l'écart le plus grave README↔code.
- Watchdog daemon (`watchdog_interval_secs = 15`).
- Rotation automatique du journal d'audit.

### 🐛 Incohérences
- `unreachable_unchecked` à auditer dans `crates/ebpf-prog/src/main.rs:101`.
- README annonce 6 vues, code en a 7.

### Tests
**270 passants, 0 failed** — supérieur aux 250 annoncés.

## 4. Audit UX

### Forces
- Tokens design centralisés (`crates/ui/src/app.css`), composants réutilisables typés (`Button`, `Card`, `Modal`, `Table` virtualisée, `Toast`, `Skeleton`, `EmptyState`).
- Architecture stores propre (`audit`, `connections`, `rules`, `decisions`, `status`, `dashboard`, `toast`).
- Popup décision style Little Snitch : fenêtre Tauri dédiée (`alwaysOnTop`, `skipTaskbar`), urgence progressive (warning → critical pulsant), file navigable.
- `prefers-reduced-motion` respecté (`app.css:251`).
- Confirmations destructives présentes pour suppression de règle.

### 🔴 Problèmes bloquants
- **Audit pagine au lieu de virtualiser** alors que `Table.svelte` propose déjà du virtual scroll (`audit/+page.svelte:215-260`). Anti-pattern sur firewall produisant des milliers d'événements.
- **Killswitch sans confirmation** (`+layout.svelte:308`) : un clic coupe ou réactive le réseau, sans modal ni undo. Risque mistap mobile élevé.
- **Popup décision : `Esc` ferme la fenêtre Tauri sans envoyer de réponse** → décision pending jusqu'à expiration. Aucune action « Différer ».
- Pas d'ErrorBanner global pour la perte de connexion daemon.

### 🟠 Modérés
- Sidebar mobile : tap target ~6px (sous WCAG 2.5.5 / 44×44).
- Filtres Connexions/Audit non debouncés → re-filtre à chaque keystroke.
- **Aucun raccourci clavier sur le popup décision** — pas d'`Enter`/`Esc`/chiffres. Contradictoire pour cible power-user Linux.
- Pas d'i18n réelle (un seul `lib/i18n/fr.ts`) ; `aria-label` codés en dur.
- Toggle règles sans `role="switch"` + `aria-checked`.
- RuleForm sans prévisualisation ni validation inline.

### Accessibilité — 3 priorités
1. Focus trap dans `Modal.svelte` + restitution du focus à la fermeture ; ajouter `role="switch" aria-checked` aux toggles de règles.
2. Remonter `--text-tertiary: #636366` (3.4:1) à `#8a8a8e` minimum (WCAG AA 4.5:1).
3. Raccourcis clavier dans `DecisionPrompt.svelte` (`a` autoriser, `b` bloquer, `Esc` différer) avec rendu `<kbd>` dans les boutons.

### Responsive
Trois breakpoints fonctionnels (desktop, tablette icônes-seulement, mobile bottom-bar). À surveiller : topbar+killswitch sur mobile, sidebar mobile non scrollable horizontalement avec 6 items + badge.

## 5. Audit design visuel

### Stack constatée
Tauri 2 + SvelteKit 5 + **CSS pur** (pas de Tailwind). Tokens dans `crates/ui/src/app.css`. Direction artistique réelle commentée : **macOS Dark Mode** (et non "cyber/néon").

### Forces
- Design system cohérent et bien tokenisé : `--bg-*`, `--text-*`, `--accent-*`, `--space-*`, `--radius-*`, échelle 4/8 px.
- Palette macOS System Colors (#0a84ff, #34c759, #ff453a) — choix sûr et professionnel.
- Composants typés et réutilisables ; `Table.svelte` fait du virtual scrolling avec sticky header.
- `prefers-reduced-motion` géré, `:focus-visible` global, `color-scheme: dark`.
- Pas de noir pur (`#1c1c1e`) — bonnes pratiques dark mode.
- Glassmorphism utilisé avec mesure (4 occurrences `backdrop-filter`).

### 🟠 Faiblesses
- **Iconographie : emojis dans la sidebar** (`+layout.svelte:43-49`) — rendu OS-dépendant, **anti-pattern majeur** pour une app premium.
- **Mismatch direction artistique** : prompt annonce "cyber/néon", code commenté `macOS Dark Mode`. Identité non tranchée.
- Logo absent : `static/favicon.png` est 128×128 8-bit gray+alpha ; pas de SVG, pas de favicon multi-tailles. Assets Tauri/Svelte/Vite par défaut encore présents.
- Police système `-apple-system` → fallback chaotique sur Linux (souvent DejaVu Sans).
- Pas de zebra-striping sur tableaux denses.
- `StatCard:hover` mort (border même valeur).
- `Card glow` exposé mais jamais utilisé (YAGNI).
- `Button` sans variantes `outline` / `link` / `ghost` complètes.

### 🔴 Critiques
- Contraste `--text-tertiary #636366` sur `--bg-primary #1c1c1e` ≈ 3.4:1, **sous WCAG AA 4.5:1**.
- `Sidebar.svelte:167` utilise `color: #000` brut — seul pur noir du codebase, brise le système.
- `backdrop-filter: blur(20px)` plein écran sur Linux/WebKitGTK : performance dégradée selon GPU. À profiler.

### Maturité du design system : **6/10**
Solide squelette technique, finition d'amateur. ~50-60% du polish de Little Snitch ; ~2 semaines de travail design ciblé pour atteindre 80%.
