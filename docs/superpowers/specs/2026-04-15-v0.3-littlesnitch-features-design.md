## Overview / Vue d'ensemble

SysWall v0.3 adopts key features from Little Snitch for Linux: domain/IP blocklists, DNS snooping for real-time hostname resolution, traffic graphs, event merging for performance, a network kill-switch with undo, and advanced search/filter in connections.

SysWall v0.3 adopte les fonctionnalités clés de Little Snitch pour Linux : blocklists de domaines/IP, DNS snooping pour la résolution hostname temps réel, graphiques de trafic, fusion d'événements pour la performance, un kill-switch réseau avec undo, et la recherche/filtre avancé dans les connexions.

## SP4 — Mergeable Events / Événements mergeables

### Goal / Objectif

Prevent event flooding during high traffic by merging similar events within a time window.

Prévenir le flood d'événements lors de trafic intense en fusionnant les événements similaires dans une fenêtre temporelle.

### Architecture

- Add a debounce buffer (100ms window) in `TokioBroadcastEventBus`
- `ConnectionDetected` events for the same connection (same 5-tuple) within the window are merged: keep the latest, sum bytes
- `ConnectionClosed` events are never merged (always forwarded)
- UI side: `connections.ts` store already merges updates by ID — no change needed

### Configuration

```toml
[monitoring]
event_merge_window_ms = 100
```

### Files

- Modify: `crates/infra/src/event_bus/mod.rs`
- Modify: `crates/daemon/src/config.rs` (add field)
- Modify: `crates/daemon/src/bootstrap.rs` (pass config)

### Tests

- Unit test: publish 5 ConnectionDetected events for same 5-tuple within 100ms, verify only 1 emitted
- Unit test: publish ConnectionDetected + ConnectionClosed, verify both emitted
- Unit test: publish events for different connections, verify all emitted

## SP5 — Network Kill-Switch with Undo / Kill-switch réseau avec undo

### Goal / Objectif

One-click button to cut all network traffic instantly, with ability to restore previous state.

Bouton en un clic pour couper tout le trafic réseau instantanément, avec possibilité de restaurer l'état précédent.

### Architecture

**Backend:**
- New gRPC RPC: `SetNetworkEnabled(enabled: bool)` in `SysWallControl`
- When disabled: daemon adds nftables rule `drop all` at priority 0 (before everything)
- When re-enabled: removes that rule
- State tracked in daemon memory (not persisted — safe default is enabled on restart)
- Optional timer: `SetNetworkEnabled(enabled: false, duration_secs: 300)` for temporary cutoff

**Frontend:**
- Toggle button in sidebar header (green shield = enabled, red = disabled)
- Toggle button in dashboard stat cards area
- Confirmation dialog before disabling ("Couper tout le réseau ?")
- Timer UI: dropdown with presets (5min, 15min, 30min, 1h) or custom
- Undo toast: "Réseau coupé. [Annuler]" for 5 seconds after disabling

### Files

- Modify: `proto/syswall.proto` (add RPC + message)
- Modify: `crates/daemon/src/grpc/control_service.rs` (implement RPC)
- Modify: `crates/infra/src/nftables/` (add drop-all rule method)
- Modify: `crates/ui/src/lib/components/ui/Sidebar.svelte` (toggle button)
- Modify: `crates/ui/src/lib/stores/status.ts` (network enabled state)
- Modify: `crates/ui/src/lib/api/client.ts` (new API call)

### Tests

- Integration test: call SetNetworkEnabled(false), verify nftables drop rule exists
- Integration test: call SetNetworkEnabled(true), verify drop rule removed
- Unit test: verify daemon starts with network enabled

## SP1 — Domain/IP Blocklists

### Goal / Objectif

Automatically block known malicious/tracking domains and IPs using text-based blocklists, similar to Pi-hole but integrated in the firewall.

Bloquer automatiquement les domaines et IP connus (malware, trackers, pubs) via des blocklists texte, comme Pi-hole mais intégré au pare-feu.

### Architecture

**Data model:**
- Blocklist files in `/etc/syswall/blocklists/` (one entry per line, `#` comments)
- Default files shipped: `blocked_domains.txt`, `blocked_hosts.txt`
- Each blocklist has metadata: name, source URL (for auto-update), enabled flag, entry count

**Domain model:**
- New entity: `Blocklist` with id, name, path, enabled, entry_count, last_updated
- New port: `BlocklistRepository` (trait) — load, list, reload, check_domain, check_ip
- New infra: `FileBlocklistRepository` — reads files, indexes in `HashSet<String>` for O(1) lookup

**Integration with PolicyEngine:**
- Blocklists are checked BEFORE user rules (lowest precedence, like Little Snitch)
- If a connection's destination IP or resolved hostname matches a blocklist entry → `ConnectionVerdict::Blocked` with `matched_rule = "blocklist:<list_name>"`
- Blocklist matches generate audit events with category `blocklist`

**gRPC:**
- `ListBlocklists()` → returns all blocklists with stats
- `ReloadBlocklists()` → hot-reload from disk
- `SetBlocklistEnabled(id, enabled)` → toggle individual lists

**UI — New "Blocklists" page:**
- Table: list name, entry count, enabled toggle, source URL, last updated
- Import button: upload a blocklist file or paste a URL
- Stats: total blocked connections, top blocked domains
- Link to download popular blocklists (StevenBlack, EasyList, etc.)

### Files

- Create: `crates/domain/src/entities/blocklist.rs`
- Create: `crates/domain/src/ports/blocklist.rs`
- Modify: `crates/domain/src/services/policy_engine.rs` (check blocklists)
- Create: `crates/infra/src/blocklist/mod.rs` (FileBlocklistRepository)
- Create: `crates/app/src/services/blocklist_service.rs`
- Modify: `proto/syswall.proto` (add RPCs)
- Modify: `crates/daemon/src/grpc/control_service.rs`
- Modify: `crates/daemon/src/bootstrap.rs`
- Create: `crates/ui/src/routes/blocklists/+page.svelte`
- Create: `crates/ui/src/lib/stores/blocklists.ts`
- Ship: `config/blocklists/blocked_domains.txt`
- Ship: `config/blocklists/blocked_hosts.txt`

### Tests

- Unit test: FileBlocklistRepository loads file, check_domain returns true for listed domain
- Unit test: PolicyEngine blocks connection when destination matches blocklist
- Unit test: PolicyEngine allows connection when no blocklist match
- Unit test: hot-reload updates the index
- Integration test: full flow from blocklist file to connection blocked

## SP2 — DNS Snooping

### Goal / Objectif

Capture DNS responses in real-time to automatically associate IPs with hostnames without additional reverse DNS queries.

Capturer les réponses DNS en temps réel pour associer automatiquement IP → hostname sans requête DNS reverse supplémentaire.

### Architecture

**Approach:** Parse DNS response packets from conntrack events on port 53. When we see a DNS response (UDP src port 53), extract the answer records (A/AAAA/CNAME) and populate the cache.

**New component:** `DnsSnooper` in `crates/infra/src/dns/snooper.rs`
- Listens to conntrack events, filters for UDP port 53 responses
- Parses DNS wire format (minimal parser for A/AAAA/CNAME answer records)
- Populates a shared `DnsSnoopCache`: `DashMap<IpAddr, (String, Instant)>` with TTL from DNS response
- Handles CNAME chains (resolve to final hostname)

**Integration:**
- `ConnectionService` checks `DnsSnoopCache` BEFORE calling `DnsResolver` (reverse DNS)
- If cache hit → use snooped hostname (faster, more accurate since it's the actual name used)
- If cache miss → fall back to existing reverse DNS with LRU cache

**UI:**
- New column "Hostname" in connections table (already have remote_hostname but rarely populated)
- Tooltip on IP addresses showing the resolved hostname
- Dashboard "Top Destinations" shows hostname when available instead of raw IP

### Files

- Create: `crates/infra/src/dns/snooper.rs` (DnsSnooper + minimal DNS parser)
- Create: `crates/domain/src/ports/dns_snooper.rs` (DnsSnoopCache trait)
- Modify: `crates/app/src/services/connection_service.rs` (check snoop cache first)
- Modify: `crates/daemon/src/bootstrap.rs` (wire DnsSnooper)
- Modify: `crates/daemon/src/supervisor.rs` (spawn snooper task)
- Modify: `crates/ui/src/routes/connections/+page.svelte` (hostname column)
- Modify: `crates/ui/src/lib/stores/dashboard.ts` (show hostnames in top destinations)

### Tests

- Unit test: parse a DNS response packet, extract A record
- Unit test: parse CNAME chain
- Unit test: cache stores and retrieves hostname with TTL
- Unit test: ConnectionService uses snooped hostname over reverse DNS

## SP6 — Advanced Search & Filters / Recherche et filtres avancés

### Goal / Objectif

Powerful search syntax in the connections page, inspired by Little Snitch's filter bar.

Syntaxe de recherche puissante dans la page connexions, inspirée de la barre de filtre de Little Snitch.

### Architecture

**Unified search bar** with structured query syntax:
```
app:firefox dest:google.com port:443 verdict:blocked direction:outbound state:established
```

**Parser:**
- Split query into tokens on spaces
- Tokens with `:` are key-value filters
- Tokens without `:` are free-text search (match against all fields)
- Keys: `app`, `dest`, `src`, `port`, `sport`, `dport`, `proto`, `verdict`, `direction`, `state`, `user`, `hostname`, `rule`
- Special: `ip:192.168.0.0/16` supports CIDR matching

**Implementation:**
- New function `parseSearchQuery(query: string)` in connections store
- Returns structured `SearchFilters` object
- Applied in the `localFiltered` derived store
- CIDR matching via simple bit-mask comparison (no library needed for /8, /16, /24)

**UI enhancements:**
- Replace individual filter dropdowns with unified search bar
- Autocomplete suggestions based on visible data (app names, IPs, hostnames)
- Filter chips below the search bar showing active filters (removable)
- Saved filters in localStorage (star icon to save, dropdown to load)

### Files

- Create: `crates/ui/src/lib/utils/search-parser.ts`
- Modify: `crates/ui/src/routes/connections/+page.svelte` (unified search bar, chips)
- Modify: `crates/ui/src/lib/stores/connections.ts` (structured filter)

### Tests

- Unit test: parse "app:firefox port:443" → { app: "firefox", port: 443 }
- Unit test: parse "google.com" → free-text search
- Unit test: CIDR match "192.168.1.50" against "192.168.0.0/16" → true
- Unit test: filter chips render and remove correctly

## SP3 — Traffic Graphs / Graphiques de trafic

### Goal / Objectif

Real-time and historical traffic visualization with lightweight charts.

Visualisation du trafic en temps réel et historique avec des graphiques légers.

### Architecture

**Library:** uPlot (35KB, used by Little Snitch, optimized for time-series)

**Dashboard graph:** Replace the empty traffic trend with a real-time chart
- X axis: time (60s sliding window)
- Y axis: bytes/s (dual axis: sent + received)
- Two series: allowed traffic (green), blocked traffic (red)
- Updates every 1 second from the existing `trafficTrend` store

**Connection detail graph:** Mini-chart in expanded connection panel
- Shows bytes sent/received over the connection's lifetime
- Ring buffer of 60 data points (1 per second)
- Sparkline style (small, no axes labels)

**Data flow:**
- Store `traffic.ts` already samples connection counts every 1s
- Enhance to also track `bytes_sent`/`bytes_received` deltas
- No database storage — in-memory ring buffers only (1h retention max)

### Files

- Add: `crates/ui/package.json` → `uplot` dependency
- Create: `crates/ui/src/lib/components/ui/TrafficChart.svelte` (wrapper around uPlot)
- Modify: `crates/ui/src/lib/stores/dashboard.ts` (track bytes, not just counts)
- Modify: `crates/ui/src/routes/dashboard/+page.svelte` (replace trend placeholder with chart)
- Modify: `crates/ui/src/routes/connections/+page.svelte` (mini-chart in detail panel)

### Tests

- Visual verification: chart renders with mock data
- Store test: ring buffer maintains correct size
- Store test: bytes delta calculation is accurate
